CollERP, Architecture Map

A multi-tenant ERP serving education, corporate, healthcare, and nonprofit verticals. Go Fiber + GORM + PostgreSQL on the back, Next.js 14 + Apollo + Redux Toolkit on the front, with a tenant-aware terminology layer and a generic approval engine.

Key data flows

1, Login + tenant resolution

Email/password -> JWT -> tenant scope

+
  1. User submits to POST /auth/login.
  2. Handler verifies bcrypt password, signs JWT carrying userID, tenantID, role, isSuperAdmin.
  3. Frontend stores token and tenantId in localStorage; Axios + Apollo attach them as Authorization + X-Tenant-ID.
  4. Subsequent calls hit Authenticate middleware which populates request locals, then domain handlers filter by tenant_id.
2, Terminology layer

Vertical-aware labels

+
  1. On login, frontend calls GET /terminology.
  2. Backend returns labels keyed off the tenant's type (education / corporate / healthcare / nonprofit).
  3. terminologySlice caches the map; useTerminology() resolves a label key (e.g. "Student") to "Patient" or "Member" per tenant.
3, Approval engine

Dynamic multi-step approvals

+
  1. Admin builds an ApprovalFlow with ordered ApprovalSteps, scoped to an ApprovalProcessType.
  2. A user raises a request via POST /approval-requests; backend resolves the active flow and records the first pending step.
  3. Each approver hits /:id/approve or /:id/reject, generating an ApprovalAction; approval_callbacks.go fans out to the domain (leave, etc.) when terminal.
4, Bulk CSV pipeline

Schema-driven upload

+
  1. Resource declared in backend/handlers/bulk/schema_*.go (columns, validators, FK lookups).
  2. Client downloads template (/bulk/:resource/template), edits in ui/BulkUpload/EditableTable, then calls /validate.
  3. On success, /submit inserts rows in chunks under the BodyLimit of 16 MiB.
5, Payroll generation

Templates -> assignments -> payrolls

+
  1. Admin defines SalaryTemplate records (basic + components).
  2. Employees are linked via SalaryAssignment (single or bulk).
  3. POST /payroll/generate snapshots templates + attendance + leave into Payroll rows; status flows draft -> approved -> paid; PDFs served from GET /payroll/:id/pdf.
6, Attendance + calendar

Marking, summary, shortage

+
  1. Teacher/admin marks attendance via GraphQL (markAttendance, bulkMarkAttendance); Holiday + CalendarSettings exclude non-working days.
  2. Reports compute summary / shortage via REST so the Redux holidaySlice can feed it synchronously.
  3. Admin can export full attendance to CSV via POST /attendance/export-csv.

Notable architectural decisions

Hybrid REST + GraphQL

CRUD-heavy domains migrated to GraphQL (Apollo) for typed selection. REST kept for auth, file uploads, exports, calendar settings, and the bulk pipeline, which all need binary bodies, custom envelopes, or sync Redux consumption.

Tenant scoping by JWT claim

No row-level security; every handler filters by tenant_id from JWT. Super admin sits on the platform tenant and bypasses scope.

Vertical-neutral terminology layer

Same schema, different labels. TenantType drives the /terminology map; UI never hardcodes "Student".

Schema-driven bulk uploads

Adding a new bulk-importable resource is a single file in handlers/bulk/schema_*.go, no route plumbing or UI changes.

Salary domain redesigned

Legacy per-employee salary_structures dropped at boot; current world is reusable SalaryTemplate + SalaryAssignment. A read-only shim still serves the legacy endpoint.

Generic approval engine

Any module can plug into ApprovalFlow, terminal actions fan out via approval_callbacks.go (currently driving leave approvals).

Component-per-page colocation

app/[tenant]/(dashboard)/X/page.tsx stays a thin shell; the real component lives in components/pages/[tenant]/(dashboard)/X/Page.tsx with sub-components in the same folder for easy navigation.

AutoMigrate on every boot

Idempotent and additive; a side migration uses a separate connection with FK constraints disabled to handle the Employee <-> Salary/Payroll cycle.
